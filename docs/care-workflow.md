# 照护提醒与重复计划

## 使用

1. 在“家庭”中修改“我的照护称呼”，如“妈妈”“Alex”。其他成员可以通过现有邀请码加入；每位设备身份都可以设置自己的称呼。
2. 添加宠物，进入“照护 → 安排照护”，填写事项与首次时间。重复频率可选仅一次、每天或每周。
3. 每天/每周计划按创建时设备的 IANA 时区重复。首次时间须在过去 24 小时至未来 29 天内；每周在相同星期几和当地时间重复。夏令时缺失的时刻顺延，之后恢复原本墙上时间；秋季重叠时刻只生成一次。
4. 开启“到时提醒”并允许系统通知。每台设备分别授权；应用不会在首次启动时直接弹通知授权。
5. 家人在待照护列表勾选完成。切换“记录”查看操作者、完成/撤销动作与时间；切换“已完成”可以撤销误点。
6. 在“重复计划”中停止计划：取消未来未完成事项，保留已完成、逾期事项和全部操作历史。停止后不会继续生成，可新建另一个计划。

“待照护”显示尚未完成的事项，包括预生成的未来事项；“记录”目前展示最近 100 条动作。删除宠物仍会清理该宠物的计划、事项与历史。成员删除身份后，保留的共享历史会显示“已退出的家人”，不再保留其姓名关联。旧版本已完成事项不会凭空补造操作者和历史。

## 时间与同步

- Java 保留计划的原始当地时间和时区，每次生成独立事项，数据库以 UTC 时间保存。
- 后端在启动 10 秒后、之后每小时补充未来 30 天事项；创建计划和看板同步也会补充，数据库唯一约束阻止同一计划同一时刻出现重复事项。
- 后端长时间离线后，仅回补最近 30 天和未来 30 天，已经生成的更早记录保留。
- App 返回前台、前台每 30 秒、用户下拉刷新及成功操作后同步。
- 在多设备同时点击完成时，事务按家庭串行并锁定事项；重复设置相同状态不会重复写入事件。完成/撤销均在服务端记录。

## 提醒边界

已接入 iOS / Android 本地通知，尚未接入 APNs/FCM 远程推送。手机仅能为自己最近同步到的事项提醒；App 关闭后家人在其他设备完成，本机不能即时得知，需要再次同步才会取消旧提醒。断网启动会保留已排定提醒，不将连接失败视为空任务列表。

最多安排最近 60 条未来、未完成的事项，给 iOS 通知队列留出余量。超出数量或超过已同步时间范围的事项需要再次打开 App 补充。关闭提醒、删除最后身份、取消事项等操作同步后会更新本地通知队列。点击通知打开照护看板并尝试同步，不直接标记完成。

Android 使用 `inexactAllowWhileIdle`，无需精确闹钟权限；系统省电、勿扰和通知权限可能影响展示或延迟时间。已补充 Android 通知权限、重启接收器、desugaring 和通知图标，以及 iOS 通知代理。

原生配置依据：[flutter_local_notifications 18.0.1](https://pub.dev/packages/flutter_local_notifications/versions/18.0.1)。依赖版本适配本机 Flutter 3.27.1；上架前应升级项目独立 Flutter 工具链并重新验证。

## 新增接口与数据

- `POST /api/tasks` 增加可选 `frequency: NONE|DAILY|WEEKLY`；重复计划还需 `zoneId`。旧的一次性创建请求保持兼容，重复计划响应包含 `planId` 和首次事项 `id`。
- `DELETE /api/plans/{id}` 停止重复计划，返回 204；跨家庭访问返回 404。
- `PATCH /api/profile`：`{"name":"Alex"}`，更新本人的称呼。
- `/api/dashboard` 新增 `me`、`plans`、`history`；事项新增可空 `planId`。
- Flyway `V2__care_plans_and_history.sql` 增加计划、操作事件、取消标记和成员称呼；V1 未改动，不重建或清空已有表。

## 验证与手工验收

运行 `flutter analyze`、`flutter test`、配置开发数据库后运行 `./mvnw test`，启动 API 后运行 `python3 scripts/smoke_test.py` 和 `python3 scripts/care_smoke_test.py`。

自动化覆盖：日/周周期、春秋夏令时、缺失当地时刻恢复、通知数量上限、完成后的取消、同步去重、家人同时完成、撤销、停止后的历史保留、越权拒绝和成员删除。

平台组件就绪后还需：真机授权/拒绝/撤销权限，创建两分钟后的事项并锁屏等待，打开通知，重启手机，跨设备完成后同步确认取消，以及 Android 省电与 iOS 勿扰模式验证。
