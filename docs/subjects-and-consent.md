# 家庭照护：宠物与家人统一档案

2026-10-21。应用内展示名称改为「家庭照护 / Family Care」，为工作名称。一个 App 管理 PET 与 HUMAN 两种照护对象；首版家人模式面向家庭日常照护，不提供诊断、剂量建议或急救保障。

## 数据兼容

V24 给现有 pets 存储增加 subject_type（默认 PET）、关系、创建者与授权字段，已有 ID、照片、计划、事项、健康记录、文件夹和历史不迁移或重建。既有 petId / /pets 路由和 dashboard.pets 保留兼容，dashboard.subjects 为相同授权范围的对象列表。对象类型建立后不可直接转换。

宠物保留品种、生日、照片与简介。家人使用称呼、关系、生日与照护偏好；家人首版不提供头像上传，未填写头像时显示人物图标，不套用猫狗照片。底部入口改为「照护对象」，可同时看到家人和宠物。

## 授权和权限

创建家人档案必须明确勾选资料授权，选择「本人」或「已获同意／有权代表」。这是创建者的授权声明及操作审计，不是被照护者身份验证或法律代理资格认证。只填写自己有权保存和共享的信息。

默认只有创建者能看到家人档案。创建者从对象详情进入「资料授权与共享」，逐个家庭成员设置不共享、查看、照护；家庭管理员不自动获得权限。查看允许查看对象、安排与记录；照护允许写入日常照护、健康记录和回忆；原家庭模块权限及临时访问到期规则仍同时生效。编辑档案、删除档案和管理共享只限创建者。

服务端在首页、照片、事项、历史、提醒、逾期、健康、回忆、导出和周／年报告中校验或过滤授权；过滤发生在分页和计数之前。未经授权的记录不会进入响应。更换共享权限会产生家庭同步失效通知，离线操作上传也重新校验，不按旧权限写入。

撤回授权会清除全部成员授权，停止新的写入、提醒及周期补充；创建者保留历史查看和管理入口。重新授权不会自动恢复成员共享。其他设备在下次联网同步后清理当前应用缓存、待同步的人物操作和本机提醒；不能保证离线设备即时清除，不能收回导出文件或截图。

退出家庭或移除成员前，创建者需先删除其家人档案，避免留下无人管理的私有资料；首版未提供创建者转交。账号删除会同时删除该账号创建的家人档案及其关联记录；原来的宠物共享资料仍按既有家庭删除规则处理。

## 按对象提供模板

- PET：喂食、换水、驱虫、疫苗、散步、洗护、自定义。
- HUMAN：用餐、喝水、用药、康复训练、复诊、日常起居、自定义。

切换对象会重置不适用的任务模板，服务端也拒绝跨对象类型的模板。家人健康记录不提供宠物驱虫类别；同一健康文件夹可继续整理体重、用药、就诊等不同类别记录。

## 用药记录

用药任务走独立的联网记录入口：人工填写药名、医嘱剂量及单位、实际服用／观察时间和备注，选择已服用、未服用、拒绝或暂停。已服用才计为完成；其余结果保留历史但不计为完成，不自动改变下一次安排。不会根据历史剂量推算新剂量。

提交同时校验事项 revision、CARE 和 HEALTH 模块权限及对象照护授权。每次请求使用稳定 ID 和内容摘要，重试不重复记账；其他人已处理时拒绝覆盖。用药结果不允许通过普通完成、撤销完成或批量跳过接口代替，逾期用药单独展示、不能随重复事项全选。周期用药每次生成独立事项。

用药结果暂需联网，不写入普通离线操作队列。记录为该次事项的不可覆盖历史；首版未提供用药结果更正流程，需要更正时保留原记录并通过健康备注说明，不使用普通撤销抹去已服用事实。

## API

- POST /api/subjects：家人档案 `{name,relationship,birthDate?,biography,consentBasis:SELF|REPRESENTATIVE,consentConfirmed:true}`。
- PATCH /api/subjects/{id}：创建者修改家人档案；不改变对象类型和授权状态。
- GET /api/subjects/{id}/access：创建者读取成员授权与最近审计。
- PUT /api/subjects/{id}/access/{memberId}：`{level:NONE|READ|CARE}`。
- POST /api/subjects/{id}/consent：`{revoke:true}` 或 `{basis,confirmed:true,revoke:false}`。
- GET /api/tasks/{id}/medication：有权查看者获取该次用药历史。
- POST /api/tasks/{id}/medication：`{requestId,revision,outcome:TAKEN|NOT_TAKEN|REFUSED|HELD,actualAt,medication,dose,notes}`。

现有表、代码包名、Bundle ID 和 API 路由中的 petcare/petId 保留兼容，不代表家人档案按宠物权限共享。真实推送、邮件、支付的外部开通状态不受本次修改影响。


## 2026-10-21 家人阶段与可叠加场景（V25）

创建或编辑家人档案可选择阶段 `ELDER / CHILD / OTHER`，对应长辈、儿童、其他／未指定。阶段由用户选择，不根据生日自动推断，也不改变已有生日或授权。

场景 `DAILY / RECOVERY` 支持同时启用，至少选择一个。新建档案默认 OTHER + DAILY；V25 迁移对已有家人档案保留 DAILY + RECOVERY，继续提供之前全部模板，用户可按实际需要调整。旧客户端更新档案不传新字段时，服务端保留原值；旧缓存缺少场景信息时使用原有模板范围。宠物不使用这些字段。

- 长辈／其他的日常场景：用餐、喝水、日常起居、照护交接。
- 儿童的日常场景：喂养、睡眠记录、成长记录、接送、照护交接；不自动安排婴幼儿喝水或填写喂养量。
- 任意阶段叠加康复：增加康复观察、康复训练、照护交接，重复模板去重。
- 用药、复诊与自定义为家人通用入口；原用药授权和结果记录规则继续生效。

阶段与场景影响任务编辑器提供的模板，不自动新增事项、不设置剂量／训练强度、不改写或删除已有任务、重复计划或历史。关闭康复场景后，已有康复安排仍可查看和处理。成长、睡眠、交接等首版为可命名的手动照护事项，不代表独立的生长曲线、睡眠分析或护工排班系统。

POST/PATCH `/api/subjects` 的档案请求新增 `lifeStage`（可省略）和 `careScenarios`（可省略；提供时必须是非空且无重复的有效列表）。dashboard 的 pets / subjects 返回相同字段，其中 careScenarios 为数组。读取与修改继续受原来的对象授权约束，不开放家庭管理员默认访问。
